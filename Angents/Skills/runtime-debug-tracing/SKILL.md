# 运行时错误追踪

## 项目适配原则

1. 立刻进入具体错误、文件、符号、日志和调用链，不先输出大段流程说明。
2. 先确认真实入口、触发路径、状态来源和首个失败位置，再提出修复。
3. 判断必须指向文件、函数、日志、协议名、资源路径或配置项。
4. 未确认根因前不加兜底、兼容入口或无关重构。
5. 场景、Loading 和 UI 缓存问题同时读取 `scene-flow-contract`；资源加载问题读取 `resource-lifecycle`；协议问题读取 `local-server-protocol`。

## 追踪顺序

1. 记录错误文本、触发操作、所在场景、账号/角色状态和是否必现。
2. 从按钮事件、生命周期、协议发送、资源加载或场景入口定位起点。
3. 向上追谁触发，向下追调用和回调，确认首个错误值或错误状态从哪里产生。
4. 区分 DB、协议、本地服务端、配置、资源和 UI 控件的状态归属。
5. 检查重复点击、空数据、乱序回包、页面关闭、切场景和异步过期。
6. 按 `AGENTS.md` 风险分流做最小修复和同路径回归验证。

## 证据映射

| 类型 | 证据 |
| --- | --- |
| 入口 | 点击绑定、生命周期、场景参数、协议发送点 |
| 状态 | DB 字段、配置字段、请求参数、服务端会话、资源 owner |
| 异步 | 请求标识、页面/场景是否仍有效、过期资源是否归还 |
| UI/资源 | FGUI 控件与控制器、MCP 读回、`XResConst`、真实资源路径 |

## 交付要求

- 说明根因、修复点、复现/验证路径和剩余风险；无法复现时明确列出已排查证据。
