# 代码质量检测

## 使用时机

- 用户明确要求“检查一下”“Review”“自查”“有没有问题”。
- 改动跨越多个模块，或涉及协议、状态归属、资源 owner、场景/UI 生命周期、异步并发和高频性能路径。
- 提交上传前需要对高风险改动执行深度质量门。
- `AGENTS.md` 快速通道只做本次 diff、直接调用点和最小专项验证，不执行本 Skill。

## 必读前置

1. 只读取本次改动直接命中的领域 Skill；代码写法问题读取 `code-style`。
2. 运行时报错、黑屏或流程卡住先读取 `runtime-debug-tracing`。
3. 提交、上传或 push 的暂存范围读取 `scoped-git-upload`。
4. 选择验证组合时读取 `references/verification-matrix.md`；需要命令时再读 `references/test-catalog.md`。

## 代码发现

1. 代码符号、调用链、反向引用和影响范围优先使用可用的代码图谱工具；未索引时先建立索引。
2. 字符串、错误文本、配置值、资源路径、Markdown、JSON 和旧名残留使用 `rg`。
3. 图谱不可用或结果不足时，说明限制并用当前文件、引用搜索和专项脚本补证。

## 检查维度

| 维度 | 必查内容 |
| --- | --- |
| 调用链 | 入口、回调、事件、协议和资源链是否完整，是否漏改引用 |
| 状态与失败 | 前置条件、数据归属、重复操作、空数据、乱序和失败回包是否明确 |
| 生命周期 | 事件、Tween、定时器、owner 和异步回调是否成对释放并防过期 |
| 性能 | 高频路径是否新增深拷贝、全量遍历、同步加载或重复布局 |
| 项目规则 | 是否违反 `AGENTS.md` 和直接命中的领域 Skill |
| 结构与验证 | 是否存在无意义中间层，以及专项测试、编译、MCP 读回或截图是否覆盖风险 |

## 检查流程

1. 锁定本次实际改动，不把无关脏文件混进结论。
2. 追入口、调用链和影响范围，再检查状态、失败分支、生命周期、性能和冗余。
3. 按验证矩阵运行能覆盖风险的最小组合。
4. 按严重度输出问题、已验证、未验证和剩余风险；无问题也要说明未覆盖范围。

## 完成条件

- 结论有文件、调用链或命令证据，不只写“看起来没问题”。
- Critical / Important 问题已修复或明确阻塞，Suggestion 不阻塞交付。
- 最终回复区分已验证、失败和未验证，不用编译结果替代业务检查。
