# 代码规范自查清单

适用于 `TypeScript`、游戏逻辑、UI、配置、类型声明、命名、重构等日常改动。

## 1. 任务开始前

| 检查项 | 说明 |
| --- | --- |
| 是否明确改动目标 | 先确认是在修 bug、补功能、调结构还是清理命名 |
| 是否定位根因 | 避免只做表层补丁 |
| 是否确认影响范围 | 至少确认调用方、配置、类型、事件、资源、UI 是否受影响 |
| 是否命中专项约束 | 命中 Cocos / FairyGUI / 生命周期时，继续阅读 `ts-cocos-fgui-guide.md` |

## 2. 文件级检查

| 检查项 | 要求 |
| --- | --- |
| 编码 | UTF-8 |
| 缩进 | 默认 4 个空格 |
| 文件头 | 新建代码文件补充 `*Author  : XW` 与 `*Desc    : 该类的作用` |
| 文件命名 | 与导出主体保持一致，避免同义不同名 |
| 自动生成文件 | 自动生成文件只做结构绑定，不直接写业务逻辑 |

## 3. 函数与逻辑检查

| 检查项 | 要求 |
| --- | --- |
| 单一职责 | 单个函数尽量只做一件事，职责混杂时主动拆分 |
| 早返回 | 优先用早返回，减少深层 `if / else` |
| 参数数量 | 参数超过 3 个时，优先改为对象参数 |
| 入参修改 | 非必要不要直接修改函数入参 |
| 返回类型 | `public`、`protected`、`private`、`async` 函数显式声明返回类型 |
| 条件判断 | 统一使用 `===`、`!==` |

## 4. 类型与命名检查

| 检查项 | 要求 |
| --- | --- |
| `any` | 非第三方接口、引擎限制、历史兼容边界外，禁止新增裸 `any` |
| 布尔命名 | 统一使用 `is`、`has`、`can`、`should` 等前缀 |
| 类名/类型名/枚举名 | 使用 `PascalCase` |
| 变量/属性/函数/参数 | 使用 `camelCase` |
| 常量 | 使用全大写下划线，或沿用项目既有常量风格 |
| 魔法值 | 公共值提取为常量、配置或枚举 |

## 5. 资源与配置检查

| 检查项 | 要求 |
| --- | --- |
| 可调内容 | 数值、掉落、关卡、商店等优先配置化 |
| 事件名 / 配置键 / 存档键 / 资源路径 | 统一集中管理，避免业务代码中散落字符串 |
| 结构改动 | 修改配置结构、字段命名、事件常量时，需同步更新相关引用与说明 |

## 6. 生命周期与释放检查

| 检查项 | 要求 |
| --- | --- |
| 注册与释放配对 | 定时器、事件、观察者、Tween、资源回调注册与释放必须成对出现 |
| `dispose` 幂等 | `dispose` 允许重复调用，不产生副作用 |
| 释放后置空 | 已释放成员及时置空，避免悬空引用 |
| 关键流程保护 | 存档、读档、奖励、扣道具等逻辑必须先校验状态再写入 |

## 7. 提交前检查

| 检查项 | 要求 |
| --- | --- |
| 调试残留 | 删除临时日志、测试分支、注释掉的大段旧代码 |
| 冗余封装 | 不保留无意义的中转函数或纯转发包装 |
| 共享逻辑 | 可复用逻辑优先提取，避免复制实现 |
| 引用完整性 | 自查受影响文件，确认无失效引用、无遗漏同步 |
| 文档同步 | 涉及规则、结构、配置、说明变更时，同步更新 `doc/` |
