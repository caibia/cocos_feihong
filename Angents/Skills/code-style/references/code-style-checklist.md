# 代码规范自查清单

适用于 `TypeScript`、Cocos 客户端代码、配置结构、类型声明、命名、重构和目录规范等日常改动。

命中专项时，按 `code-style` 主文使用时机分流。

## 1. 任务开始前

| 检查项 | 说明 |
| --- | --- |
| 是否明确改动目标 | 先确认是在修 bug、补功能、调结构还是清理命名 |
| 是否定位根因 | 避免只做表层补丁 |
| 是否确认影响范围 | 至少确认调用方、类型、命名、目录和专项 Skill 是否受影响 |
| 是否命中专项约束 | 命中专项时，按文件开头专项入口和 `code-style` 主文使用时机分流 |

## 2. 文件级检查

| 检查项 | 要求 |
| --- | --- |
| 编码 | UTF-8 |
| 缩进 | 默认 4 个空格 |
| 文件头 | 新建代码文件补充 `*Author  : XW` 与 `*Desc    : 该类的作用` |
| 文件命名 | 与导出主体保持一致，避免同义不同名 |

## 3. 函数与逻辑检查

| 检查项 | 要求 |
| --- | --- |
| 单一职责 | 单个函数尽量只做一件事，职责混杂时主动拆分 |
| 早返回 | 优先用早返回，减少深层 `if / else` |
| 参数数量 | 参数超过 6 个时，优先改为对象参数 |
| 入参修改 | 非必要不要直接修改函数入参 |
| 返回类型 | `public`、`protected`、`private`、`async` 函数显式声明返回类型 |
| 条件判断 | 统一使用 `===`、`!==` |
| 纯转发函数 | 只转调一个方法且无额外逻辑时内联到调用处 |
| 一次性变量 | 常量或配置只用一次时直接使用原值，不额外定义局部变量 |
| 判断边界 | 动态对象、外部返回和异步数据必须校验 |
| 调用换行 | 简单线性调用优先一行；只有对象字面量、回调、复杂表达式、嵌套调用或一行明显难读时拆行 |

## 4. 类型与命名检查

| 检查项 | 要求 |
| --- | --- |
| `any` | 除第三方库接口和引擎限制外，禁止新增裸 `any` |
| 布尔命名 | 统一使用 `is`、`has`、`can`、`should` 等前缀 |
| 类名 / 类型名 / 枚举名 | 使用 `PascalCase` |
| 变量 / 属性 / 函数 / 参数 | 使用 `camelCase` |
| 常量 | 使用全大写下划线，或沿用项目既有常量风格 |
| 魔法值 | 公共值提取为常量、配置或枚举 |
| 业务纯类型声明 | `app` 业务逻辑模块的 UI 参数、场景参数、事件参数、存储数据、模块数据、回调参数等集中放到 `dts/` |
| 底座与适配类型 | `base`、`fairyGUI`、Cocos 引擎适配、工具内部类型保留在对应 `.ts` 文件 |
| 运行时映射类型 | 依赖类、常量、枚举值或生成链路的类型保留在对应 `.ts` 文件 |
| item/list 数据类型 | 继承 item/list 的 `data` 使用具体 payload 类型，并保留中文属性注释 |

## 5. 基础常量与专项入口检查

| 检查项 | 要求 |
| --- | --- |
| 事件名 / 业务键名 / 字段名 | 统一集中管理，避免业务代码中散落字符串 |
| 专项 Skill 命中 | 命中专项时，按文件开头专项入口和 `code-style` 主文使用时机分流 |
| 结构改动 | 修改配置结构、字段命名、事件常量时，需同步更新相关引用与说明 |

## 6. 提交前检查

| 检查项 | 要求 |
| --- | --- |
| 调试残留 | 删除临时日志、测试分支、注释掉的大段旧代码 |
| 冗余封装 | 不保留无意义的中转函数或纯转发包装 |
| 共享逻辑 | 可复用逻辑优先提取，避免复制实现 |
| 引用完整性 | 自查受影响文件，确认无失效引用、无遗漏同步 |
| 规则与文档同步 | 执行规则更新 `AGENTS.md` 或对应 Skill；说明文档变化才同步 `doc/` |
