# 游戏运行质量

## 使用时机

- 高频循环、地图、战斗、列表、动画或批量回调可能造成卡顿、GC 或内存增长。
- 事件、观察者、Tween、定时器、延迟回调或网络回包存在重复注册、乱序、过期和释放风险。
- 关键状态写入涉及前置条件、数据归属、请求时序、重复操作或失败回滚。
- 普通单点属性修改、线性调用或无运行时风险的小改动不使用本 Skill。
- 场景/UI 创建与缓存合同读取 `scene-flow-contract`；资源 owner、加载和释放读取 `resource-lifecycle`。

## 状态与模块边界

1. UI、业务 DB、网络和本地服务端状态分清归属，通过公开接口、事件或明确数据结构交互。
2. 状态写入前校验角色、配置、权限、数量、请求时序和重复操作；失败时不先改 UI 再回滚。
3. 业务写入成功后再触发表现、提示、动画、刷新或后续流程。
4. 配置缺失、数据不合法或前置条件不满足时明确日志和结束路径，不用默认值掩盖根因。

## 事件、计时与异步

1. 事件、观察者、Tween、定时器、延迟回调和网络单元注册后必须有对应释放。
2. `dispose` 允许重复调用；释放成员后及时置空。
3. 页面关闭、切场景、请求更新或资源取消后，旧回调不得继续写状态或刷新对象。
4. 重复点击、弱网、失败回包和乱序回包必须有明确状态约束，不能用无条件成功跑通界面。

## 性能检查

1. `update`、滚动、战斗、地图、动画和批量回包中避免无必要的对象创建、深拷贝、排序、全量遍历、字符串拼接、JSON 解析和同步加载。
2. 批量 UI 变化合并刷新或增量刷新，避免同一帧大量创建、销毁节点和重复布局。
3. 配置查询、寻路和目标筛选考虑数据增长；常用路径避免 O(n²)，必要时使用索引、缓存、脏标记或分页。
4. 性能敏感改动必须说明实测方式；无法实测时给出静态证据和未覆盖风险。

## 交付要求

- 只检查本次改动直接影响的高风险路径，不把本 Skill 变成所有游戏功能的通用前置流程。
- 说明验证规模、触发频率、生命周期边界和仍未实测的平台风险。
