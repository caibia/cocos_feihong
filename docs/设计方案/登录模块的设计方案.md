# 登录模块的设计方案

## 目标

补齐一个最小可用的 `LoginView` 占位界面。界面以 `assets/resources/movie/login/login01.mp4` 为全屏循环背景，所有文本和按钮显示在视频之上；按钮只输出 `XDEBUG` 点击日志，不接入登录、选服或设置业务。

## 当前状态

- `login01.mp4` 及其 `.meta` 已存在，运行时资源地址为 `movie/login/login01`。
- `VideoUnit` 已提供循环播放和停止释放能力，`GVideoPlayer` 已启用 `stayOnBottom`，可避免 Web 平台视频 DOM 覆盖 Canvas UI。
- 旧登录脚本已删除，但 `UIDefine.ts` 仍引用 `LoginView`、`LoginServerListPopView` 和 `PvPlayView`。后两个界面不在本次占位需求内，也已不存在。

## 实现范围

### LoginView

- 新建 `assets/script/app/module/login/LoginView.ts` 及对应 `.meta`。
- 继承 `XWindow`，不加载 FairyGUI 包，不恢复旧登录业务与结构绑定基类。
- 创建全屏根容器，并在 `onRefresh` 中通过 `VideoUnit.playLoop` 静音循环播放 `movie/login/login01`。
- 视频层级固定为 `0`；文本和按钮放入独立覆盖容器，覆盖容器层级固定为 `10`。
- 覆盖内容包含标题“飞鸿江湖”、说明文本“登录界面占位”和三个按钮：“开始游戏”“选择服务器”“设置”。
- 三个按钮共用一个占位点击入口，分别输出按钮名称，日志格式为 `XDEBUGLOG.debug("[LoginView] 点击占位按钮", name)`。
- `onStageResize` 负责同步视频尺寸和覆盖控件位置，保证不同屏幕尺寸下 UI 仍位于视频之上且不越界。
- `dispose` 停止并释放背景视频；按钮事件由现有 `EventUnit` 随界面释放。

### UI 注册清理

- 保留 `UINAME.LoginView`、`UIInstanceMap` 中的 `LoginView` 映射和 `UIDefine.initUI()` 中的全屏底层注册。
- 删除 `UIDefine.ts` 中已不存在的 `LoginServerListPopView`、`PvPlayView` 导入、名称、类型映射和注册。
- 不修改登录 DB、Repo、事件、存档或场景流程。

## 异常处理

- 不提供背景图片或其他视频兜底。
- 视频资源缺失或导入失败时，沿用现有视频加载链路显式输出错误，不伪造可继续播放的状态。
- 占位按钮不触发业务调用，因此不存在请求重入或状态写入。

## 测试与验证

- 先编写失败测试，验证背景资源地址、视频层级、覆盖层级、三个按钮文案、点击日志以及销毁时的视频停止行为。
- 使用 Cocos/FairyGUI 最小桩实例化 `LoginView`，测试真实生命周期调用，不为生产类增加测试专用 API。
- 运行受影响 TypeScript 文件的定向转译检查和 `git diff --check`。
- 全量 `tsc --noEmit` 当前存在 Cocos 引擎声明、其他缺失模块和临时探针文件错误，只作为基线记录，不将其误报为本次改动结果。

## 验收标准

- 打开 `LoginView` 后，`login01.mp4` 全屏静音循环播放。
- 标题、说明文本和三个按钮均可见，并始终位于视频上方。
- 点击任一按钮只输出对应的 `XDEBUG` 日志，不改变业务状态或切换界面。
- 界面销毁后视频停止，相关对象不继续持有播放状态。
- `UIDefine.ts` 不再引用本次范围外且已不存在的两个登录子界面。
